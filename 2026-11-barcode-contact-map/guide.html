Barcode Contact Map

An interactive viewer for linked-read barcode co-occurrence counts along a chromosome, with automatic calls for off-diagonal hotspots and junction patterns. This page covers the input format, the preprocessing script, and how to read the map.

1. Input format

Reads are mapped to the reference and their positions are binned (5 kb by default). For every pair of reads that share a barcode, count how many such pairs land in each pair of bins. The result is one text file per chromosome with three whitespace-separated columns, binA_start, binB_start and count, and no header line: 

0           0           1001
0           5000        577
5000        0           577
5000        5000        1042
3000000     4500000     12
4500000     3000000     12
  • Positions are bin start coordinates in bp and must be multiples of the bin size.
  • The count is the number of shared-barcode read pairs with one read in each bin. Bin pairs with no shared barcodes are left out.
  • The matrix is symmetric: every off-diagonal pair appears twice, as a b and b a, with the same count. Diagonal cells appear once. The script checks this and stops if a mirror line is missing.
  • Lines can be in any order, separated by tabs or spaces. The file can be gzipped.
  • One chromosome per file. Contacts between chromosomes are not used.

2. Make .bcm files with preprocess.py

preprocess.py converts each input file into a compact <chromosome>.bcm bundle. It holds the contact counts plus the hotspot and junction calls. It needs Python 3.10 or newer with numpy and scipy. The script declares those dependencies inline, so with uv there is nothing to install first: 

uv run preprocess.py --input chr1_5kb_bin.stat chr2_5kb_bin.stat.gz --fai ref.fa.fai --out bcm/

This writes bcm/chr1.bcm and bcm/chr2.bcm. Without uv:

python3 -m pip install numpy scipy
python3 preprocess.py --input chr1_5kb_bin.stat --out bcm/

Expect well under a minute and a few GB of memory for a chromosome of around 100 Mb at 5 kb. Bundles are a few MB each.

To try the pipeline without real data, write a synthetic 10 Mb chromosome with a planted inversion and junction. It is the same dataset as the viewer's "Load example" button:

uv run preprocess.py --synthetic --out bcm/

Chromosome names and lengths

  • With --fai (a samtools faidx index of the reference), each file is named after the longest sequence name that its file name starts with, followed by _, . or nothing, so NC_000001.11_5kb_bin.stat becomes NC_000001.11. The index also supplies the true chromosome length. Files that match no name in the index fall back to the rule below.
  • Without --fai, the name is the file name up to the first _ or ., so chr1_5kb_bin.stat becomes chr1. The length is taken as the end of the last bin with data.
  • --name sets names explicitly, given once per --input in the same order.

3. Open files in the viewer

  • Click Open a .bcm file, or drag one or more .bcm files onto the page. With several files loaded, the Chromosome menu in the toolbar switches between them.
  • Zoom with the mouse wheel, a trackpad pinch or a double-click; drag to pan; Shift+drag a box to zoom into it. The go-to box takes a range in Mb, such as 12.3-14, or two ranges for the x and y axes, such as 2.9-3.1; 4.4-4.6.
  • The page address records the chromosome and view. Send it to a colleague who has the same .bcm files, and the view opens where you left it once they load them.
  • To host bundles next to the page, add ?src=chr1.bcm (repeatable) to the address. Data on another server must allow cross-origin requests.

4. Reading the map

Both axes are positions along the same chromosome, so the main diagonal holds pairs of nearby bins. Linked reads come from long DNA molecules, so bins within roughly one molecule length (around 100 kb) share many barcodes. Further apart, only a low background remains from barcodes that happen to be reused. Shared barcodes far from the diagonal mean the two regions sit close together in the sequenced genome even though the reference puts them apart.

Display modes

Mode (key)Shows
Enrichment (4, default)Only cells with clearly more shared barcodes than expected for their distance and coverage (a z-score above 2). The background stays blank, so off-diagonal signal stands out at any zoom.
O/E (3)Observed over expected on a log scale: red above expected, blue below.
Balanced (2)Counts divided by the coverage of the two bins.
Raw (1)Counts on a log scale.

The bars along the top and left show each bin's long-range coverage relative to the median. Grey rows and columns have too little coverage to test, often gaps or unmappable sequence. Orange bins share barcodes with everything (three times the median or more), which usually means a collapsed repeat. Both kinds are excluded from calling.

Hotspots

Green boxes mark hotspots: regions at least 300 kb apart with significantly more shared barcodes than expected. The side list ranks them by excess, the observed count minus the expected count. Tags in the list:

  • extended: the signal is spread over many 5 kb cells, as a misjoin, rearrangement or segmental duplication would give.
  • point: one 5 kb row or column holds more than 90% of the signal. This is more likely a repeat copy than a breakpoint. "Hide point-like" removes them.
  • hub N: in the top 10% by the number of other hotspots sharing a 1 Mb window, which marks regions that link to many places.

Junctions

If reference positions A and B are actually adjacent in the sequenced genome, then a bin u away from A and a bin v away from B are about u + v apart. They share barcodes the way bins that distance apart on the diagonal do. That gives a triangle of signal with its right angle at (A, B), fading over about one molecule length. Which side of the corner it falls on depends on how the two ends are joined. In the upper triangle, rows are the smaller coordinate A and run down, and columns are B and run right:

WedgeJoined in the sampleUsual reading
up-left --left of A to left of Bone end of an inversion of A..B
down-right ++right of A to right of Bthe other end of that inversion
up-right -+left of A to right of Bdeletion of A..B in the sample, or a misjoin
down-left +-right of A to left of Btandem duplication of A..B

The Junctions tab lists the calls by type. A butterfly-inversion has the up-left and down-right triangles at the same corner, which is what a balanced inversion of the whole segment between A and B gives. A butterfly-deldup has the other pair. A junction has a single triangle, a block is enrichment with no corner structure, and a point is a single hot 5 kb line. The j key toggles the wedges on the map.

Keys

With the map focused: arrow keys pan, + and - zoom, 0 resets the view, 1 to 4 switch mode, h and j toggle hotspots and junctions, and n and p step through the open list.

5. How hotspots and junctions are called

Expected counts

Each bin gets a coverage factor f: its shared-barcode count with bins at least 1 Mb away, divided by the median over bins that have any. Coverage far from the diagonal reflects copy number and mappability rather than molecule length. The expected count for bins i and j is

expected(i, j) = E(|i - j|) * f(i) * f(j)

E(d) is the coverage-corrected count at distance d. Below 1 Mb it is estimated separately for each distance as a trimmed mean, so a single outlier can't inflate it. Beyond 1 Mb the background is flat, so one pooled constant is used. Bins with f < 0.1 (low coverage) or f ≥ 3 (stripes) are not tested.

Hotspots (50 kb)

  1. Sum the counts into 50 kb bins and test every pair of valid bins at least 300 kb apart.
  2. Model each count as negative binomial with mean expected. Fit the dispersion by maximum likelihood, separately for pairs under and over 1 Mb apart, with the most extreme 0.1% left out.
  3. Call a cell significant when it has at least 10 read pairs, observed/expected of at least 3, and a p-value below 0.01 divided by the number of tests (Bonferroni).
  4. Merge significant cells within two bins of each other into regions, and rank the regions by excess.
  5. Significant cells inflate the coverage of their own bins. Their counts are therefore removed from the coverage factors and the test is run a second time.

Junctions (5 kb)

  1. The template for a corner at (A, B) is a triangle up to 100 kb on a side. Its value at offsets (u, v) is the near-diagonal decay curve at distance u + v, times the coverage of the two bins.
  2. For each candidate corner and each quadrant, fit the template's strength above background under the same negative binomial model. Score the fit as a likelihood ratio.
  3. A quadrant only counts if its signal spreads in two directions away from the corner. This keeps single hot lines from posing as triangles.
  4. Corners are scored as the best single quadrant or opposite pair. Nearby duplicates within 50 kb are merged, and the vertex is placed on a 2.5 kb grid.
  5. The score cutoff (450) comes from scoring random boxes away from hotspots. On a chromosome of the 93 Mb it was calibrated on, it allows fewer than one expected false call. Longer chromosomes have more places to look and so more expected false calls (see limitations). Each call reports its expected false-positive count and a q-value.

The Enrichment colour uses the same model at whatever resolution is on screen: z = (observed - expected) / sqrt(max(expected, 1) + phi * expected²). Only cells with z > 2 are coloured. It is a display score; only the hotspot and junction lists come from the tests above.

6. Limitations

  • Events that touch a grey low-coverage bin or an orange stripe bin are not tested.
  • Pairs closer than 300 kb are excluded, because normal linked-read signal dominates there.
  • The far tail of the counts is heavier than the model expects. Treat very small p-values as a ranking, not as exact probabilities.
  • The junction cutoff and the rules that assign types were calibrated on a single 93 Mb chromosome at 5 kb. For other chromosomes or bin sizes, run --junction-null 150000 once. It prints the score at which one false junction is expected, so you can check whether 450 still fits.
  • An insertion of 10 to 50 kb gives two nearby junctions that are merged into one call.
preprocess.py --verify re-checks a bundle: the header, the decoded counts against the input (with --input), and that the stored calls can be reproduced. Run it after processing a new dataset.
